# Sequential post-turn signal checks

User-approved design: check each eligible signal individually with an exact Y/N response after all other semantic background work, including accepted world state, narrative focus and fragment reranking. Implement without further approval pauses.

Signals represent actual events in the just-completed player/GM exchange, not intentions, possibilities or relevance of guidance. Fragment selection no longer emits signals. Signal checks are independent of embedding retrieval and narrative focus; focus supplements the complete exchange.

Keep existing signal assignments API compatible. Add `SignalCheckDefinition(name, description, conditions)` and default-empty `signalChecks` to turn/prefill/warmup requests. Signals in frontmatter accept optional nonblank `description` and optional flag `condition`. Explicit descriptions define event predicates independently of fragment paths. For older scenarios lacking descriptions, derive descriptions from signal-bearing fragment paths (or the signal name if no path exists); preserve legacy condition eligibility where applicable. All condition checks use the turn-start flags and assignments apply in declared order after all checks, without same-turn chains. Multiple signal references must not duplicate calls for equivalent predicates. Conditions on explicitly described signals come from signal declaration, not unrelated fragment selection.

For each eligible signal use the same held llama.cpp slot, session and deterministic shared prompt prefix containing completed conversation and accepted world state. Append a common event-check instruction before the varying signal description. Use grammar `root ::= "Y" | "N"`, `n_predict=1`, prompt caching. Strict exact Y triggers; N or invalid response does not. Do not accumulate check exchanges in game history. Emit per-check diagnostics with prompt/result/cache/evaluation/time metrics and signal outcomes/flag deltas.

Order: primary generation -> existing context/world-state work -> existing fragment rerank -> signal checks -> necessary canonical cache restoration -> completion carrying final flags. The next model turn must wait for final checks and use final flags; browser IndexedDB persists them. Typing remains available via existing input-ready event. No server-owned persistent session flags. Retain background outcome support where already used. Failures must not leave the slot leased forever or falsely commit positive signals; log failures with request IDs only outside local TRACE.

Canonical warmup after analysis is technical cache restoration, not semantic analysis. Preserve exact prompt-prefix and retained warm-slot contract tests for new, resumed and following games; never weaken tests. Measure actual tokens_cached/tokens_evaluated for live claims. Do not start/restart the user's game server without need.
