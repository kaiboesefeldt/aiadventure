# Player Message Suggestion

Pressing Tab twice in the focused message field starts a suggestion. Text already entered forms its beginning. While the request waits or generates, the field is read-only and shows an appropriate status. Esc also cancels waiting, stops a running generation and immediately unlocks the field. Already displayed text remains. Normal Tab behavior and existing keyboard operation remain available outside the recognized gesture.

The browser incrementally transfers text from a cancellable stream into the field. The suggestion request is subject to the existing session coordination and is admitted only after all background work, including world state, signal checks, reranking and warmup, has completed. Cancellation ends the associated model request without cancelling other tasks. Errors unlock the field and are shown. Stale stream events must not change the field after cancellation or a session switch.

Suggestion generation uses the existing session slot. The suggestion instruction and model response are temporary and do not enter game history; all existing game history remains intact. Because the suggestion prompt does not necessarily match the templated turn prompt, a regular prefill for the actually visible text starts after completion or cancellation. The shared cache prefix, including already entered text, is reused as far as technically possible. This runs asynchronously; newer input supersedes older prefills. A following turn waits for correct coordination and preserves the existing prompt-prefix and slot-lease contract. Cache reuse is checked using llama.cpp metrics, not inferred from visible text.

Tests cover the keyboard gesture, status, streaming, read-only behavior and cancellation while waiting and generating. Server tests check ordering against all background work, cancellation and release, and prefill after suggestions and newer edits. The existing cache contract tests for new and resumed games and following turns remain; finally, run `./gradlew check`.
